# AIskin App Store 上架就绪度审计报告（源码级）

- 审计范围：`codex/app-store-readiness` 分支，仓库 `easelearnai/ios_aiskin3`
- 审计方式：**纯静态代码审查**（`grep`/文件阅读），未编译、未签名、未提交 App Store
- 审计日期：2026-08-10
- 审计环境：Linux 容器，**无 macOS / 无 Xcode / 无 `swiftc`**（已用 `which xcodebuild swiftc swift` 验证，均不存在）

> ⚠️ **重要声明：本报告未验证 Signed Archive。**
> 当前环境无法运行 `xcodebuild build/archive`、无法代码签名、无法运行 XCTest、无法用 Xcode 的隐私清单合并/校验工具验证 `PrivacyInfo.xcprivacy`、无法验证 Release 配置下运行时行为（如日志是否真的输出、网络请求实际响应等）。以下所有结论均基于源码静态阅读得出，**不构成"已完成 App Store 上架准备"的结论**，正式提交前必须在真实 macOS/Xcode 环境中完成 Archive 签名、TestFlight 真机验证、隐私清单 Xcode 校验。

## 1. PrivacyInfo.xcprivacy —— ❌ 完全缺失

- 全仓库搜索（`find . -iname "*.xcprivacy"`）无任何结果，`project.pbxproj` 中也无 `PrivacyInfo`/`xcprivacy` 引用。
- 代码中确认使用了 Apple "Required Reason API" 类别之一：`UserDefaults`（`AIskin/Services/AuthService.swift` 第 56/72/73/92/93/127/132/137 行），根据 Apple 隐私清单要求，使用 `UserDefaults` API 必须在隐私清单中声明批准的原因代码（如 `CA92.1`），否则从 2024 年起 App Store Connect 会在构建上传阶段直接警告/拒绝。
- App 会收集并回传邮箱/手机号/姓名/性别/人脸照片/皮肤分析结果等数据到自有后端（`https://www.lunzo.site`），隐私清单中还应声明 `NSPrivacyCollectedDataTypes`（联系信息、照片、健康相关的皮肤分析数据）及是否用于追踪（当前未发现追踪 SDK，可声明 `NSPrivacyTracking = false`）。
- **结论：必须新增 `PrivacyInfo.xcprivacy` 文件并加入 App target，声明 Required Reason API 用途及收集的数据类型，否则会在 Xcode 15+/App Store Connect 校验阶段被拦截。**

## 2. AI 图片处理前的告知与同意 —— ❌ 不合规

- 皮肤检测入口 `AIskin/Components/skin-analysis/welcomeContentView/SkinDetectionWelcome.swift` 的"拍照检测"/"从相册选择"按钮，点击后直接触发系统相机/相册选择器（`AIskin/Views/SkinStatusView.swift` 第 42-59、132-136 行），选中图片后 `onChange` 立即调用 `processImageFile` → `startAnalysis()`，**图片会被立即上传至云端 AI 分析，期间没有任何应用内的告知弹窗或二次确认**，Info.plist 里的 `NSCameraUsageDescription`/`NSPhotoLibraryUsageDescription` 只是系统级权限描述，不等同于"AI 处理前明确告知并取得同意"。
- 产品成分识别（`AIskin/Components/product/AddProduct.swift`/`ImageUploader.swift`）同样是选图即上传，无专门告知。
- 注册页 `AIskin/Components/login/RegisterForm.swift` 第 302-337 行有一个"我已阅读并同意 使用条款 和 隐私政策"复选框，且 `validateForm()`（第 435-439 行）确实会校验必须勾选才能注册——**但"使用条款"和"隐私政策"只是纯文本 `Text`，没有绑定任何 `Link`/`NavigationLink`/`onTapGesture`/URL**，全仓库（含 `doc/`）搜索不到任何隐私政策或用户协议正文/链接，即这两个词是"死文字"，用户点了也无法阅读到具体内容。
- **结论：既没有在拍照/上传这一具体动作前做专门的 AI 处理告知，注册时的笼统同意勾选也因为链接不可用、政策不存在而形同虚设。需要：①在人脸照片上传前增加专门的说明与同意步骤（说明照片将上传云端由 AI 分析、是否留存等）；②让"隐私政策"“使用条款”真正可点击并跳转到真实文档。**

## 4. 日志 / 硬编码密钥 / 测试账号 / 敏感信息泄露

- **日志数量**：`AIskin/` 下 `print()` 调用约 **877 处**，全部为普通 `print`，未使用 `#if DEBUG` 包裹，Release/TestFlight/正式包中同样会执行并写入系统日志（可被 `sysdiagnose`/Console.app/USB 连接的 Xcode 控制台读取）。
- **最严重问题：明文密码被打印**。`AIskin/Services/APIClient.swift` 的 `post`/`put`/`patch` 方法中有：
  ```swift
  if let bodyString = String(data: request.httpBody!, encoding: .utf8) {
      print("📤 Request Body: \(bodyString)")
  }
  ```
  登录/注册请求体（`LoginRequest`/`RegisterRequest`）里包含**明文密码**，会被完整打印到日志（第 225-227、432-434、505-507 行）；同时响应体也会被完整 `print`（含用户信息、皮肤分析结果等）。
- **PII 明文日志**：`AIskin/Services/UserApiService.swift` 在注册/登录/获取用户信息等多处直接 `print` 邮箱、手机号、姓名（如第 77、95、105、125、134、152、161、180、203 行）。
- Token 处理相对克制：仅打印前 20 个字符（`token.prefix(20)`），泄露面比密码小很多，但仍建议连这部分也去掉。
- **硬编码密钥/密文**：对 Swift/Markdown/JS 源码做了正则扫描（AWS Key、GitHub Token、Slack Token、`sk-`前缀、PEM 私钥头等常见模式），**未发现任何硬编码的云服务密钥或私钥**；也没有 `.env` 文件。
- **测试账号**：App 主 target 内没有硬编码测试账号；`AIskinTests/` 下各测试文件会用时间戳生成一次性邮箱（如 `test_\(timestamp)@example.com`）+ 固定密码 `TestPassword123`，但由于 `APIClient.baseURL` 是写死的生产地址 `https://www.lunzo.site/api`（无测试环境注入点），**运行这些测试会直接对生产后端注册真实账号、调用真实 AI 分析接口**，属于测试卫生问题（非 App Store 拒审直接原因，但会污染生产数据，且 `AIskinTests/APIClientTests.swift` 第 34 行还断言 `baseURL` 应为 `http://localhost:5000/api`，与当前生产地址不一致，说明该测试目前已经是过期/会失败的状态——**未实际运行验证，仅代码比对得出**）。
- **较严重的敏感信息泄露**：`AIskinTests/1924903380_1761459787694.jpg` 是一张**真实可辨认人脸的自拍测试图**（已读取确认为近距离清晰人脸照片），被 `RealImageTests.swift` 第 143-146 行加载后作为"真实图片测试"上传到生产 AI 接口。把一张真人人脸照片提交进代码仓库并在测试中反复回传生产服务器，本身就是数据处理风险，建议：①从 Git 历史中彻底清除该文件（如果仓库会公开或分享）；②改用已获得授权/合成的测试图片；③测试环境应指向 staging，不应打到生产库。

## 5. 与 Apple 审核账号问题相关的代码侧准备 —— ⚠️ 存在风险

- 未发现任何演示/游客账号或审核旁路逻辑。
- 登录 (`AIskin/Components/login/LoginForm.swift`) 与注册 (`RegisterForm.swift`) 的 UI **只暴露手机号方式**，且手机号校验正则为中国大陆格式 `^1[3-9]\d{9}$`（`isValidPhone`）；虽然 `AuthService`/`UserApiService` 底层已支持邮箱注册/登录，但当前 UI 没有任何入口调用邮箱流程。**如果 App Store 审核人员没有中国大陆手机号（且后端要求真实短信/格式校验），将无法自行注册或登录完成审核**，这是历史上很常见的拒审/需要提供演示账号的场景。
- "忘记密码" 是占位页（`LoginForm.swift` 第 247-253 行：`Text("忘记密码功能")`），没有实际找回流程——如果提供给审核的账号密码有误且没有额外沟通,审核人员将无法自助恢复。
- "帮助与反馈"提交按钮同样是空实现（`ProfileView.swift` 第 305-345 行 `FeedbackModal`，点击"提交"只是 `dismiss()`，未真正发送），审核时点击体验为"假成功"，建议要么接后端接口，要么先隐藏该入口。
- 未接入任何第三方登录 SDK（无 Sign in with Apple / 微信 / Google 等依赖，`project.pbxproj` 中无 `XCRemoteSwiftPackageReference`，也没有 Podfile/Package.swift），因此不会触发 Guideline 4.8（第三方登录必须同时提供 Sign in with Apple）的问题，这点是好的。
- **建议**：提交审核前在 App Store Connect 的"App 审核信息"备注中，提前用生产环境注册好一个演示账号（手机号+密码）并附上说明，或在 UI 中开放邮箱注册通道，同时补齐忘记密码与反馈提交的真实实现，避免审核人员因无法登录或遇到"死按钮"而拒审。

## 结论与优先级建议

**当前源码状态不具备直接提交 App Store 审核的条件**，需要至少解决以下"阻断级"问题：

1. 补充 `PrivacyInfo.xcprivacy`（声明 `UserDefaults` 等 Required Reason API + 收集的数据类型）
2. 移除/包裹掉会打印明文密码、邮箱、手机号、完整请求响应体的 `print` 语句（尤其是 `APIClient.swift`）
3. 提供真实可访问的隐私政策与用户协议内容，并让注册页文字可点击跳转；补充设置页"隐私政策"入口
4. 认证 Token 迁移到 Keychain 存储
5. 为人脸照片上传增加专门的 AI 处理告知/同意步骤
6. 解决审核可登录性问题（演示账号 / 邮箱登录入口 / 忘记密码可用）
7. 清理测试用真人照片与生产环境测试污染问题

**再次强调：本报告仅为源码级静态审计，未在 macOS/Xcode 环境完成签名归档（Signed Archive）、未做真机/TestFlight 验证、未验证隐私清单能否通过 Xcode 校验，不代表"已完成 App Store 上架准备"。**
